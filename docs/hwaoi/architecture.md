# 实现边界与下一阶段

历史原型记录：DKB 已作为新的项目基础导入。下文的 `src/` 路径指整理前原型；现位于 `tools/hwrecomp` 和 `tests/prototype/include`。当前状态见 `port-status.md`。

## 已实现的数据流

```text
用户 NUP（原文件只读）
  → 已验证的目录与更新包选择
  → work/game/exefs（逐文件 SHA-256）
  → NSO 段与动态符号分析
  → 显式选择的小函数 ARM64→C
  → Windows x64 DLL
  → 与 Unicorn 的受控状态比较
```

输入：Title ID `04003F40232DE000`，本体包 0、更新包 1，更新 NCM version `196608`。当前 `main` Build ID 为 `659cb288b5c5b2b49853add616c0d5bf4ea4e1ba000000000000000000000000`。容器没有可靠的 display-version TLV，具体显示版本仍未知。

`src/hwrecomp/nup.py` 只负责安全读取，不解密；`nso.py` 不执行重定位；`a64.py` 只翻译选定范围；`src/runtime/hwr_runtime.h` 只提供寄存器和单段映射内存，不提供 Nintendo 系统服务。

## 证据强度

- 44 项测试覆盖合成的格式错误、指令、内存和标志位等情况。
- 13 个真实小函数通过 832 组确定性随机输入对照，比较全部 X 寄存器、SP、PC、NZCV 和 4096 字节测试内存。
- 此结果不是实际主机对照，不证明其他函数、完整 ABI 或游戏流程正确。
- `.text` 的线性指令分类包含填充和内嵌数据。主模块存在大量未支持字，因此不能将比例称为移植完成率。
- 最初的报告保留在 `work/reports`，其中旧路径反映整理前的位置；新的验证使用新目录。原 ROM 没有移动或改写。

## 后续里程碑

1. 加入 MOD0、ELF 动态表/RELA 与 EH frame 分析，建立跨模块符号和函数边界证据；处理间接控制流。

3. 确定运行时模块布局与链接方案，移植必要系统服务。每项替代都应有返回值、内存与线程行为的验证。
4. 分别处理 NVN2 调用、Ampere shader、Vulkan、音频、输入和 RomFS 按需读取。
5. 按“模块加载 → 主入口 → 标题画面 → 首场战斗 → 存档/长期运行”逐级报告，不提前声明完整可玩。
